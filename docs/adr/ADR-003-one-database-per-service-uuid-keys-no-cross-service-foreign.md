# ADR-003: One database per service, UUID keys, no cross-service foreign keys

- **Status:** Accepted (Phase 3, 11 Oct 2026)
- **Deciders:** Product owner (client), development lead

## Context

Services must own their data (master spec §11) and never touch another service's tables.

## Decision

Each service has its own PostgreSQL database (identity, catalog, assessment, learning, billing; ai in Release 2) and its own DB user with rights only to it. Locally and on the first EC2 deployment these live on one PostgreSQL server. Primary keys are UUIDv7 generated by the application (time-ordered, index-friendly). References to other services' entities are plain UUID columns validated through APIs or events.

## Consequences

No cross-database joins; read models (billing.exam_view, learning.topic_view) are kept up to date from events. Referential integrity across services is eventual.

## Alternatives considered

Shared schema (rejected: breaks ownership); separate PostgreSQL servers per service (unnecessary cost at launch).
